# Grundfos MP 204 (motor protector)

**Status: reading, events, trip and reset work on hardware** (FlowHub F103,
2026-11-25/26). `mp204 stop` and the full bench test below have not been run.

Item IDs and commands: *Operating the MP 204 Electronic Motor Protection Unit
via GENIbus or G100*, Ed. 2.28, May 2011 (chapters 5-8, 12.3, 14). They are in
`src/poll_table.c` (firmware), `lib/genibus/mp204.c` (commands) and
`tools/profiles/mp204.json` (PC apps).

## Identification

| What | Value on the bench unit |
|---|---|
| Family / type | **7 / 1** |
| Address | **231** (0xE7): the address of an MP 204 with no number set. Give each unit its own number with Grundfos GO before adding others. |
| Group | 247 |
| `df_buf_len`, bus mode | 77, 14 |

Terminals: **A, Y, B** (GENIbus data A, reference/screen, data B). C, C and SH
beside them belong to the Pt100/Pt1000 input; 95-96 is the trip relay, 97-98
the signal relay. See [hardware](../hardware.md) for the bus wiring.

## Items polled

Set up for a **3-phase motor**: line voltages v12/v23/v31 and mean, currents
i1-i3 and mean, motor temperatures (Tempcon, Pt), current asymmetry,
frequency, cos phi, power, energy, running and power-on time, number of starts,
insulation resistance, act_mode1/2, alarm code and three warning bytes.

- With a **1-phase motor** the line voltages, `i_asym` and `cos_phi` read n/a;
  use `v_phase` (class 2, ID 27, 2 bytes) instead.
- Some items are measured in one motor state only, otherwise n/a:
  `r_insulation` with the motor **off** (101 = more than 1000 kOhm);
  `t_mo1`, `i_asym` and `cos_phi` with the motor **on**.
- `t_on` (power-on time, minutes) stops while the MP 204 is unpowered. The
  master console uses it to tell a power failure from a bus fault.

### Status bytes

| Item | Bits |
|---|---|
| act_mode1 (2/95) | 0-2 mode: 0 started, 1 tripped (protection), 2 tripped (test/commanded), 3 stopped (commanded, no alarm); 3 motor off; 4 trip relay 95-96 closed; 5 signal relay 97-98 closed; 7 protection disabled |
| act_mode2 (2/96) | 0-1 system: 0 power-up, 1 operating, 2 device fault; 2 ready; 3 pending alarm |
| alarm_code (2/144) | 0 none, 2 missing phase, 3 PTC/thermal switch, 4 too many auto restarts, 9 phase sequence, 15 communication, 18 commanded trip, 20 insulation low, 32 overvoltage, 40 undervoltage, **48 overload**, **56 underload**, 64/71 overtemperature, **111 current asymmetry**, 112/113 cos phi max/min, 120 aux winding, 123/124 start/run capacitor |

Current-related trips are 48, 56 and 111 (and 2 for a lost phase). The alarm
log (class 2 IDs 153, 157, 161, 165, 169, newest first) is part of `mp204`.

## Stop / trip / reset

| Console command | Sends | Effect |
|---|---|---|
| `mp204` | reads only | mode, relays, alarm, last five alarms |
| `mp204 stop` | `TRIP_A` (3, 95) | trip relay opens, no alarm (Tripped 3) |
| `mp204 trip` | `TRIP` (3, 81) | like the Test button, alarm 18 (Tripped 2) |
| `mp204 reset`, then `mp204 reset yes` within 15 s | `RESET_ALARM` (3, 2) | clears the trip **and can start the motor** |

- Before sending, the unit must identify as an MP 204 (7/1) and be operating.
  Stop and trip need mode `started`; reset is refused while started or with
  protection disabled.
- Sent once, never retried. `result:"ok"` means mode and trip relay were read
  back as requested. `still_tripped`: the MP 204 is in Tripped 1 after the
  reset. `unconfirmed`: **treat the motor state as unknown** and check at the panel.
- `relay1_closed:0` is the relay's reported state, not proof the contactor opened.
- The raw `cmd`, `set` and `setv` have none of these checks. `cmd 3` is a
  factory reset and `cmd 12` disables motor protection.

### Bench test (not yet run in full)

Motor power isolated: control voltage only on the contactor, or a lamp/meter
on 95-96. An emergency stop must work without the board. The MP 204 may
restart on its own (`auto_restart:1`) and starts at power-on unless
`power_on_stop:1`. Write down `t_auto_restart` before step 6.

1. `target 231`, `mp204`. Expect `started`, `relay1_closed:1`, `protection:1`.
   **Write down `alarm` with no trip** (0 is assumed). If already tripped, stop
   and find out why.
2. `mp204 stop`. Expect `ok`, `tripped3_stop`, `relay1_closed:0`, no red Trip
   light, 95-96 open on the meter.
3. `mp204 stop` again: `not_started`, `sent:false`.
4. `mp204 reset`, wait over 15 s, `mp204 reset yes`: `not_armed`, 95-96 still
   open. Then `mp204 reset`, `mp204 reset yes`: `ok`, 95-96 closed.
5. `mp204 trip`: `ok`, `tripped2_test`, alarm 18, red light on, 95-96 open and
   97-98 closed. Wait past `t_auto_restart`: it must stay tripped. Reset as in 4.
6. Simulated protection trip: `set 5 15 2` (undervoltage bit, assumed to match
   `alarms1_enable`), wait for the trip delay, then `mp204`: expect
   `tripped1_protection`, alarm 40, newest log entry 40. Reset as in 4 should
   clear the simulation; confirm with `get 5 15` = 0 (otherwise `set 5 15 0`).
7. Stop once more, pull bus wire A, wait 10 s: 95-96 must stay open (the bus
   watchdog is off by default). `mp204 reset` must fail to read, and
   `mp204 reset yes` must report `bus_error`, `sent:false`. Reconnect.
8. Power-cycle the MP 204 from `tripped3_stop` and note whether the relay
   closes. The profile says it does unless `power_on_stop:1`.
9. Finish with `get 5 15` = 0, `stats`.

## Power-failure logging

With the master console, each session logs to `logs/<date-time>_unit231/`
(see [tools](../../tools/README.md)):

| What fails | What the MP 204 does | Logged as |
|---|---|---|
| A phase that does not feed it | keeps running, trips: alarm 2 / 40 | PHASE VOLTAGE LOW (which phase, all three voltages), CHANGE, ALERT |
| The phases that feed it, or all | goes dead, bus falls silent | LINK DOWN with the last readings before the loss |
| Power returns | answers again | LINK UP: "WITHOUT POWER for about N min" (from `t_on`) or "STAYED POWERED" (bus fault); STATUS AFTER RECOVERY with the alarm log |
