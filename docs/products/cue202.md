# Grundfos CUE202 (pump frequency converter)

**Status: read-only, draft profile.** The CUE answers on GENIbus and its values
can be read and logged, but **the meaning of each data item is not known yet**.
That needs Grundfos' *CUE GENIbus functional profile*, which is not published
online: request it from Grundfos support or a distributor.

> The CUE drives a pump motor. Class 3 commands and class 4/5 writes can start
> the pump, change its speed or its configuration. None are offered until they
> come from the functional profile. Do not use the raw `cmd`, `set` or `setv`
> console commands on it.

## How this CUE behaves on the bus

- **It answers every ID.** Unused items return 255 ("no data") instead of an
  "unknown ID" NACK, in classes 2, 4 and 5. `probe` therefore lists 1-255 and
  cannot tell which items exist.
- **INFO is reliable.** Items with real scaling return a unit, a factor and the
  standard or extended format, and multi-byte values mark their low bytes
  (`bo:1`). The draft profile and the table below come from an INFO sweep of
  class 2, IDs 1-255.
- **The firmware's built-in table is for the MP 204.** When the CUE is the only
  unit, discovery targets it and the firmware tries to read MP 204 items from
  it; those batches fail with `bad_apdu`. Nothing is written, but use the
  master console (`tools/geni_master.py`), which switches the built-in polling
  off and uses the CUE profile instead.

## Using it now

```bash
python3 tools/geni_master.py
```

Scan bus: unit 32 is matched to **CUE202 (DRAFT - item names unknown)**
(`tools/profiles/cue202_draft.json`). "Use this unit" reads the scaling,
polls every 2 s and logs to `logs/<date-time>_unit32/`.

What works with the draft: live values, `readings.csv`, LINK DOWN / LINK UP
with the outage length in minutes. What does not: the power/communication
verdict (no confirmed power-on counter), phase-loss checks (phase voltages not
identified), status decoding, alarms, commands.

Wiring is the same as for any GENIbus unit (A, B and the reference/screen to
the transceiver; see [hardware](../hardware.md)). Check the CUE's own
installation manual for its GENIbus terminal numbers.

## Finishing the profile

When the functional profile arrives:

1. Copy `tools/profiles/cue202_draft.json` to `cue202.json` and delete the draft.
2. Give each item its real `name` and `label`; drop items that do not matter.
3. Add `decoders` for the status and alarm items, and an `alert`.
4. Set `power_on_counter` (if the CUE has one) and `phases` (if it reports
   phase voltages), so LINK UP and phase checks work as for the MP 204.
5. Add `commands` only from the profile, each with a `confirm` text that says
   what physically happens. They go to the CUE unchecked.
6. Check every value against the CUE display.

Format: [tools/profiles/README.md](../../tools/profiles/README.md).
